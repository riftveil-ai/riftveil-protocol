# Changelog

## v1.0.0 (Professional) · 24 October 2026 · First public release

The first published version of the Riftveil Protocol. Everything below is in this release.

- **Protocol** (`protocol/RIFTVEIL_PROTOCOL.md`): the four absolute rules (never validate, never rewrite, never conclude, never assume the challenge is complete) and the independence rule (the second reader is never the author); the root failure mode, automation bias with a human signature; an input gate and a source rule (the submitted project and the user's context only, no web search, no outside facts); triage on three qualitative criteria (reversibility, impact scope, financial commitment, read on the scale of the organisation), with the escalation rule shown in one Criteria line and no amount, headcount or duration setting a level on its own; impact scope at its widest step: "the whole organisation, or people outside it at scale (a client base, authorities, the public)"; five levels of challenge (the question, the answer, the reasoning, the perspective, the applicability) with procedural detection heuristics for every technique; a pre-action review for agent plans, with a fourth criterion, reach, and a mandatory "Before this runs" section; a report that opens with a six-line Record box and ends on questions, each assumption with a named human verifier and each question with an owner where the role can be inferred; a report that can be read without knowing the protocol: the levels examined are named (question, answer, reasoning, perspective, applicability), along with those that were not; the findings line gives the total, then the number by impact; a fixed legend of the levels and the triage follows the Criteria line; a report written without the first person, with Riftveil as the subject when it speaks of its own work; second-level Markdown headings; a pre-mortem finding labelled "Pre-mortem:"; an optional follow-up block completed by the human, never by the model; record metrics a team can count; a final check before sending; fixed strings for a French report; a self-awareness block with sourced limitations; a worked example.
- **Companions**: the compact version (`RIFTVEIL_PROTOCOL_COMPACT.md`) for agent builders with a character limit; the version for Microsoft 365 Copilot agents (`RIFTVEIL_COPILOT_AGENT.md`), under 8,000 characters, without agent-plan review or the follow-up block. The files are in `protocol/`, with no version number in their names.
- **JSON schema** (`schema/riftveil_report.schema.json`, draft 2020-12) with a validated example; `protocol_version` "1.0.0".
- **Examples**: three full reports, each with the submitted AI output (LOW, MODERATE, CRITICAL). The worked example and the published examples follow the protocol's own source rule and rule 1: what the project does not show is written as missing, never as a checked fact.

## Before publication (working versions, not published)

The protocol went through working versions numbered 1.1 to 1.3.5 before this release. None was released in this repository; none should be cited or pinned. Their content is part of v1.0.0. In order:

- **Origin**: a five-level challenge framework, written in French and English.
- **1.1**: the protocol as a system prompt: chain-of-thought pre-analysis, procedural heuristics for every technique, triage on three criteria, domain protocols (pharma and healthcare, finance, legal, tech), edge cases, the five-section report ending on questions, a worked example, the self-awareness section, the compact version and the JSON schema.
- **1.2**: the root failure mode named at the top; agent plans handled as pre-action review with "Before this runs"; a named human verifier for every assumption, an optional owner per question, one permitted closing line; two sourced limitations added; citations checked against their sources.
- **1.3**: the independence rule; the Record box; the follow-up block (first drafted as "Attestation", renamed because a report certifies nothing; the JSON field keeps the name `attestation`); record metrics; reach for agent plans; in the sector editions, a block on what the regulator expects to see.
- **1.3.1**: the input gate and the source rule; the Criteria line; length that never lowers the triage; Level 3 and Level 4 results reported as findings, the pre-mortem always run at CRITICAL and for agent plans; the impact at the end of every finding label; a final check before sending; the whole report in the user's language, with fixed French strings; the submitted answer called "the project".
- **1.3.2**: triage without amounts, headcounts or durations: qualitative steps read on the scale of the organisation; an amount without the size of the organisation recorded as "not stated (amount without scale)".
- **1.3.3**: four precision fixes after a review of reports produced in three assistants: quotation marks mean the project's exact words; "What holds up" never sets the project against an alternative it did not take; the verifier is never the project's presumed author; with a trigger alone, the report is in the language of the project.
- **1.3.4** (23 October 2026): a Record that can be read without knowing the protocol (levels named, findings by impact, a fixed legend of the levels and the triage); "an AI model" in the note on reasoning.
- **1.3.5** (24 October 2026): the writing of the report tightened after tests on five texts: the pre-mortem label, nothing after the last level examined, Record lines with no dash added, second-level headings.
